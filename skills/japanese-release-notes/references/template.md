# 更新告知テンプレート

これは構成の例。波括弧は実データへ置き換え、内容がない節は削除する。重大な破壊的変更・停止条件はダウンロードや手順より前へ移す。

```markdown
# {製品名} {版}

{今回の更新の要点と利用者への効果を 1〜3 文で。}

## ダウンロード

| 環境・用途 | ファイル |
| --- | --- |
| {対応 OS / アーキテクチャ} | [{実行用 asset 名}]({固定版の直接 URL}) |
| 対応ソース | [{ソース asset 名}]({固定版の直接 URL}) |

{checksum・署名・出自情報と、検証・導入手順への案内。}

## ハイライト

- {利用者にとって重要な改善を簡潔に。}

## 新機能

- {新たにできることと使い方。}

## 変更

- {以前からある挙動の変化と影響。互換性・移行があれば明記。}

## 修正

- {発生条件と改善後の挙動。裏付けのない修正済み判定はしない。}

## 導入・更新

{前提、入手・検証、新規利用、既存更新、再起動・停止の順に案内。}

## 技術情報・検証範囲

{採用 commit・差分・PR・CI、実施した検証とその限界。}

## 既知の問題・注意事項

{判明している制約と必要な対処。未検証は問題の存在・不存在と区別。}

## ライセンス・対応ソース

{適用ライセンス、クレジット、第三者通知、同じ版の対応ソースへの導線。}
```

長い検証コードは末尾の独立した節へ置いてよい。必須情報は折り畳みに隠さず、先頭のダウンロード節から検証節へ案内する。小規模更新なら「変更と修正」などへ統合する。
