# Development Skills

開発作業の説明・記録の品質を、実行するAIサービスにかかわらず揃えるためのスキル集です。共通の手順は `SKILL.md` と同梱資料に置き、導入方法・呼出し記法・サービスへの接続は環境別に扱います。

## 収録スキル

| スキル | 目的 | 状態 |
| --- | --- | --- |
| [japanese-release-notes](skills/japanese-release-notes/SKILL.md) | 利用者に変更点を伝え、配布物と導入・更新へ案内する | 収録済み |
| `write-pr-description` | レビュアーに問題・変更・結果・検証を説明する | 追加候補・未実装 |
| `write-commit-message` | コミットに含む一つの変更単位を記録する | 追加候補・未実装 |
| `name-branch` | 作業目的が分かる有効なブランチ名を作る | 追加候補・未実装 |

リリースノート、PR説明、コミットメッセージ、ブランチ名は同じ開発カテゴリで管理し、用途ごとに独立したスキルとして選択します。同じカテゴリであることを理由に全スキルを連鎖させません。

## 共通に守ること

1. 対象プロジェクトのスキル、編集規則、用語、既存のテンプレートを先に確認します。共通版の採用は差分をレビューして行い、プロジェクトで育てた手順を自動上書きしません。
2. 変更の根拠と、読み手にとっての結果を説明します。ファイル名や作業経緯を列挙するだけで済ませません。
3. 実装・テスト・ビルド・配布・実機確認を区別します。古い版の検証を現在の成功として報告しません。
4. 版番号、パス、識別子、URL、既存の重要な注意を正確に保持します。Conventional Commits等の形式は対象プロジェクトが採用している場合に従います。
5. 文面や識別名の作成と、投稿・公開・コミット・ブランチ作成の操作を区別します。操作権限はその時点の依頼と環境から確認します。

| 用途 | 根拠にする範囲 |
| --- | --- |
| リリースノート | 前回の配布版から対象版への変更、実際の配布物、互換性情報 |
| PR説明 | 固定したbase/headで定まるレビュー対象差分と、その版に対する検証記録 |
| コミットメッセージ | 実際にコミットへ含める差分。無関係な未ステージ変更を混ぜない |
| ブランチ名 | これから行う依頼の目的と既存の命名規則。完成差分は要求しない |

## AIサービスと実行環境

通常のスキルはChatGPT・Claude・Geminiのいずれかを必須にしません。必要な読取・調査・検証には、その環境で許可された同等の機能を使います。特定のMCP、保存API、CLIを共通手順の唯一の入口にしません。

ChatGPT Sitesなど特定サービスの運用そのものが目的なら、`update-chatgpt-sites-preview` のように対象サービスが分かる名前にします。これは対象サービスの識別であり、実行エージェントを不要に限定する規則ではありません。PythonやGit等の実行環境要件も、AIサービス依存と分けて明記します。

`agents/openai.yaml` はOpenAI向けの配布設定です。他環境への対応は、その環境の正式な導入方法と設定で行います。ファイル形式の共通化だけで、各サービスの自動選択・接続・実行まで検証済みとは扱いません。

## 日本語リリースノートを使う

[スキル本体](skills/japanese-release-notes/SKILL.md)と[テンプレート](skills/japanese-release-notes/references/template.md)を使用します。Minecraft Release Changelogsの見渡しやすさを参考にした構成で、他製品の文面・ロゴ・固有表現は含みません。

1. `skills/japanese-release-notes` ディレクトリを、参照資料・配布設定・LICENSE・NOTICE・OUTPUT-PERMISSION.mdを含めて取得します。
2. 利用する環境の正式なスキル導入手順に従い、認識された名前と版を確認します。既存の同名スキルは差分を確認してから更新します。
3. 対象プロジェクトの制作手順を確認し、必要なスキルを明示的に指定します。環境が明示呼出し専用の設定を提供する場合は、その設定も適用します。

依頼例：

> japanese-release-notes を使って、対象版の変更点と配布物を確認し、日本語のリリースノートを作成してください。

GitHub Releaseの本文を更新する場合は、対象Releaseの編集権限と依頼が必要です。このスキルは新規公開、タグ変更、配布物の差し替え、ソフトの実行を許可するものではありません。
